# 中文参考摘要

**状态：** Draft v0.5。Study B 和 Study C 的真实模型结果尚未产生；本文件仅用于辅助理解，正式论文使用英文摘要。

基于大语言模型的智能体会在运行时将系统指令、用户消息、检索文档、对话记忆、工具定义与输出，以及中间执行轨迹组合为模型可见上下文。这个过程可能引入上下文膨胀，即对于特定任务而言重复、无关、陈旧或不必要地冗长的内容。本论文研究如何利用具有来源追踪能力的运行时审计来检测、量化、定位和控制此类内容，同时避免将 token 减少直接等同于任务效用得到保留。

本论文设计了版本化的上下文来源 schema 和 Python 审计框架，在每次模型调用前捕获客户端序列化请求。框架记录有序分段、来源归属、token 数量、标准化哈希、请求载荷哈希、检测器输出、人工标注、反事实结果和缓解决策。其证据模型严格区分人为注入的扰动、启发式指标、独立人工参考标签和反事实可移除性。

实验由三个研究组成。Study A 是覆盖检索、记忆和工具工作流的受控扰动基准，通过 LangChain 和 Custom ReAct 两条执行路径运行，共包含 1,188 次已完成任务运行和 1,596 条调用轨迹。其与 1,122 个注入标签的完全一致只证明管线内部一致性，而不代表真实场景中的检测准确率。Study B 增加 60 个公开数据集的 held-out 任务、120 个自然生成的最终上下文，以及两位真人评审者全覆盖的双盲分段标注。Study C 增加配对反事实删除实验，并在相同 token 预算下比较来源感知缓解方法与 LLMLingua-2。Study B 和 Study C 的软件已通过 mock 端到端验证，但真实校准与 held-out 调用仍由外部协议注册门禁阻止。

在 Study A 中，缓解方法平均减少 48.85% 的上下文 token，95% 置信区间为 [42.67%, 55.31%]。任务成功率变化为 -6.11 个百分点，95% 置信区间为 [-12.22, -0.56]。因此，受控 fixture 中的 token 减少已经成立，但任务表现的非劣效性没有成立，现有证据与性能退化风险一致。在受控设计下，工具输出具有最高的注入膨胀比例，但该排序不能推广到自然智能体。

本论文目前的贡献包括具有来源追踪能力的运行时审计框架、受控扰动基准，以及一套可独立检验的自然轨迹验证与效用感知缓解协议。关于外部检测准确率、人工一致性、反事实可移除性和压缩基线的最终结论，必须依据完成注册后的 Study B 和 Study C 真实实验结果。
